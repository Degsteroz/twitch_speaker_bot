# RoastBot

RoastBot — self-hosted Twitch-сервис: принимает команду в чате или активацию
награды Channel Points, безопасно генерирует короткий «роаст» через Anthropic,
озвучивает его локальным Piper и отправляет текст и звук в OBS Browser Source.

> Для агентов и разработчиков, которые открывают репозиторий впервые, есть
> подробное руководство [AGENTS.md](AGENTS.md): команды, инварианты и открытые вопросы.

## Архитектура

- `web` — React/Vite-панель стримера и владельца.
- `overlay` — Browser Source для OBS; получает события по WebSocket.
- `api` — Fastify API, OAuth Twitch, настройки, админка, подписанные аудиоссылки.
- `twitch` — IRC и EventSub WebSocket, обновление OAuth-токенов.
- `worker` — очередь pg-boss, лимиты, Anthropic, модерация, TTS и outbox.
- `tts` — FastAPI-обёртка над локальным Piper.
- `postgres` — PostgreSQL 16, данные приложения и очередь pg-boss.
- `caddy` — HTTPS и маршрутизация двух доменов.

Снаружи доступны только Caddy и два домена. PostgreSQL, TTS, web и overlay живут
только во внутренней Docker-сети без выхода в интернет; `api`, `worker` и
`twitch` дополнительно подключены к сети `egress`, потому что им нужны Twitch,
Anthropic и Telegram. Портов эта сеть не публикует. Общий volume `audio` используется API и worker, volume
`models` — TTS, данные PostgreSQL и Caddy хранятся отдельно.

## Требования

Для production: Linux x86_64/arm64, Docker Engine 24+, Compose v2, DNS A/AAAA
для `APP_DOMAIN` и `API_DOMAIN`, открытые 80/tcp, 443/tcp и 443/udp. До установки
желательно иметь не менее 2 ГиБ свободной RAM и 10 ГиБ диска. Лимиты контейнеров:
TTS 1 ГиБ/1 CPU, PostgreSQL 512 МиБ, API и worker по 512 МиБ; суммарная реальная
нагрузка зависит от модели и трафика.

Для разработки: Node.js 20+ (CI и образы используют 22), pnpm 10.18.3,
Python 3.12 и PostgreSQL 16. Проверка хоста ничего не меняет:

```sh
./deploy/preflight.sh
```

## Быстрый запуск production

1. Скопируйте `deploy/.env.example` в `deploy/.env` и замените все заглушки.
2. Создайте Docker volume моделей и поместите два файла голоса Piper, описанные ниже.
3. Настройте Twitch-приложение и DNS.
4. Запустите:

```sh
docker compose --env-file deploy/.env -f deploy/docker-compose.yml config
docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d --build
docker compose --env-file deploy/.env -f deploy/docker-compose.yml ps
```

Одноразовый сервис `migrate` ждёт готовности PostgreSQL, применяет Drizzle-
миграции под session advisory lock и выполняет идемпотентный seed. API, worker
и Twitch не стартуют до его успешного завершения. Повторный `up` безопасен.

## Локальная разработка

```sh
corepack enable
pnpm install --frozen-lockfile
pnpm build
pnpm test
pnpm lint
```

Поднимите PostgreSQL 16 и TTS, затем скопируйте `.env.example` в `.env` в корне
репозитория и заполните. Этот файл не попадает в git; dev-скрипты `api`,
`worker`, `twitch` и `db:*` читают его сами (`--env-file`). Затем в разных
терминалах:

```sh
pnpm db:migrate
pnpm db:seed
pnpm --filter @roastbot/api dev
pnpm --filter @roastbot/worker dev
pnpm --filter @roastbot/twitch dev
pnpm --filter @roastbot/web dev
pnpm --filter @roastbot/overlay dev
```

Для локального OAuth задайте `PUBLIC_URL=http://localhost:3000`,
`DASHBOARD_URL=http://localhost:5173` и зарегистрируйте callback
`http://localhost:3000/auth/twitch/callback`. Twitch требует точного совпадения
callback, включая схему, порт и путь. В dev-режиме overlay открывается на
`http://localhost:5174/overlay/?token=…` и сам ходит в API на порт 3000.

## Локальное демо без Docker и Twitch

```sh
pnpm demo                     # фейковые ответы модели
ANTHROPIC_API_KEY=… pnpm demo # настоящий Haiku (или ключ из корневого .env)
```

Скрипт `scripts/demo.mjs` поднимает встроенный PostgreSQL, настоящие API и
worker, dev-серверы панели и оверлея. Вход без Twitch: `http://localhost:5175/login`,
затем панель `http://localhost:5173` и оверлей
`http://localhost:5174/overlay/?token=demo-overlay-token`. Вместо Piper звучит
macOS `say` (голос Milena), на других ОС — короткий сигнал. Чат и награды Twitch в
демо не подключены.

## Twitch Developer Console

В [Twitch Developer Console](https://dev.twitch.tv/console/apps) создайте
приложение категории Website Integration. OAuth Redirect URL должен быть ровно:

```text
https://APP_DOMAIN/api/auth/twitch/callback
```

Например, при `APP_DOMAIN=app.example.com`:
`https://app.example.com/api/auth/twitch/callback`. В `TWITCH_CLIENT_ID` и
`TWITCH_CLIENT_SECRET` скопируйте Client ID и новый Client Secret.

RoastBot запрашивает только чтение: `channel:read:redemptions`, `bits:read`,
`channel:read:subscriptions`, `moderator:read:followers`, `channel:read:predictions`,
`channel:read:ads` (список — `TWITCH_SCOPES` в `packages/shared`). Публикация сообщений от имени
бота не используется. После изменения callback или scope войдите заново.

## Anthropic

Создайте API key в Anthropic Console и задайте `ANTHROPIC_API_KEY`. Установите
жёсткий месячный лимит расходов (для v1 рекомендуется $10) в самой консоли:
лимит приложения дополняет, но не заменяет лимит провайдера.

По умолчанию реплику пишет `claude-opus-5-5` ($4 / $20 за 1M токенов на вход/выход), ответ
проверяет `claude-sonnet-5-5` ($2 / $10). Около $0.012 за роаст, то есть примерно 800 роастов на
$10. `ANTHROPIC_MODEL` и `CLASSIFIER_MODEL` применяются только при первом seed; потом модели
меняются в `/admin` → «Глобальные» (миграция 0010 один раз переводит старые значения
`claude-haiku-5-5`). Параметры запроса под модель — `services/worker/src/models.ts`: Opus 5.5,
Sonnet 5.5 и Fable не отключают thinking (400), поэтому им ставится `effort: "low"` и запас
`max_tokens`; Haiku 5.5 вызывается с `thinking: {type: "disabled"}`. `temperature` не
передаётся нигде. Для Opus/Sonnet 5.5 включён серверный фолбэк при отказе модели
(`fallbacks: "default"`).

Защита бюджета в приложении: kill switch, глобальный лимит роастов
(`global_monthly_limit`, 4000), денежный лимит (`monthly_budget_usd`, $5 —
стоимость считается по токенам каждого вызова, включая неудачные) и квота
канала по тарифу. При достижении любого лимита воркер не обращается к Anthropic,
роаст получает статус `skipped` с причиной, а дашборд показывает «лимит исчерпан».

**Модель и голос по тарифу** (`/admin` → «Глобальные» → «Тарифы», миграция 0012). У тарифа есть
`premium_roasts` — сколько роастов в месяц идут на глобальной модели и лучшем голосе
(ElevenLabs → Яндекс → Piper); остальные — на `economy_model` (по умолчанию `claude-haiku-5-5`)
и `economy_voice` (`yandex` или `piper`). На Free 2 лучших роаста, на платных — все (`null`).
Счётчик — `usage_monthly.premium_roasts`, бронируется в `reserve()` под тем же advisory lock.
Классификатор одинаковый на всех тарифах. Что использовал роаст, видно в `roasts.tier`,
`roasts.model`, `roasts.voice_provider` и на странице `/roasts/<id>`. Месячный лимит роастов
в админке не редактируется: seed обновляет его из кода при каждом деплое.

**Тесты из панели** (карточка «Тест», источник `dashboard_test`) квоту канала не тратят и
кулдауны не проверяют: у них свой лимит — 5 в день на канал (`DASHBOARD_TEST_DAILY_LIMIT`,
таблица `test_usage_daily`, сутки по UTC). Kill switch, глобальный лимит и бюджет действуют,
деньги теста идут в бюджет, лучшие роасты тарифа тест тоже расходует. Симулятор в той же
карточке изображает награду, слово в чате, донат, рейд, прогноз, битсы, подписку или фоллоу:
воркер получает те же текст, описание события и цель, что и от Twitch
(`services/api/src/simulator.ts`). Под квотой панель оценивает, на сколько минут эфира её
хватит с включёнными триггерами, и подсвечивает, если меньше трёх часов.

## Голоса персонажей (ElevenLabs, Yandex SpeechKit, Piper)

Озвучка идёт по цепочке, каждая ступень со своим жёстким месячным лимитом: **ElevenLabs** →
**Yandex SpeechKit** → **Piper** (локально, бесплатно). Сбой или медленный ответ облачного голоса
передаёт реплику следующему, эфир не замолкает.

**ElevenLabs** (необязательно): `ELEVENLABS_API_KEY`, `ELEVENLABS_MODEL` (по умолчанию
`eleven_v4`, есть русский) и ID голосов `ELEVENLABS_VOICE_TSUNDERE` / `ELEVENLABS_VOICE_YANDERE`
из библиотеки голосов ElevenLabs. Героиня без ID голоса озвучивается Яндексом.
Свои героини Premium выбирают голос из списка в `/admin/characters`: пять голосов добавляет
миграция `0017`, голоса Мицуки и Аи воркер добавляет сам при старте, сэмплы записываются
автоматически. Формат WAV 24 кГц
(44.1 кГц требует Pro). Цена $0.08 за 1000 символов; лимит символов в месяц —
`elevenlabs_monthly_char_limit` в `/admin` (по умолчанию 70 000, тариф Starter даёт 75 000), учёт
в `tts_usage_monthly` (provider `elevenlabs`, атомарный резерв до запроса).

У каждого персонажа свой голос Yandex SpeechKit (API v3): цундэрэ — `julia`/`strict`,
яндэрэ — `jane`/`good` (`services/worker/src/tts.ts`). Кудэрэ — `julia`/`neutral`,
дандэрэ — `marina`/`whisper`, химэдэрэ — `dasha`/`strict`. Запросы делает `worker`: у TTS-сервиса
нет выхода в интернет. Нужен сервисный аккаунт с единственной ролью `ai.speechkit-tts.user` и
его API-ключ в `YANDEX_TTS_API_KEY`.

Локальный Piper — запасной голос: он звучит без ключа, при ошибке Яндекса, при ответе дольше
3,5 с и после исчерпания лимита. Эфир не замолкает ни в одном из этих случаев.

**Жёсткий лимит расходов.** В Yandex Cloud нет отсечки по деньгам (бюджеты только
уведомляют), поэтому лимит держит RoastBot: `/admin` → «Глобальные» → «Жёсткий лимит голосов
Яндекса», по умолчанию 300 ₽ в месяц. Рубли переводятся в запросы по тарифу 0,1626 ₽ за
запрос до 250 символов (300 ₽ = 1 845 запросов). Каждый запрос резервируется в
`tts_usage_monthly` одной атомарной операцией до обращения к Яндексу, поэтому параллельные
роасты не превышают лимит, а неудачные попытки тоже засчитываются. Месяц считается по
московскому времени, как в биллинге Яндекса. Расход виден на «Обзоре». Стоимость озвучки
также входит в долларовый бюджет сервиса.

TTS-образ содержит `piper-tts`, но модели намеренно не скачиваются при сборке. Piper — только
запасной голос, и оба персонажа женские, поэтому нужен один голос, Irina:

- `ru_RU-irina-medium.onnx`
- `ru_RU-irina-medium.onnx.json`

Скачивайте только из доверенного источника и сверяйте SHA-256. В репозитории есть
`services/tts/download_models.py`: он требует `IRINA_URL`, `IRINA_SHA256`, `IRINA_CONFIG_URL`,
`IRINA_CONFIG_SHA256` и отказывается принимать файл с неверной суммой. В `.env.example` уже
прописаны ссылки на тег `v1.0.0` репозитория `rhasspy/piper-voices` и их SHA-256 (сняты
2026-10-23). `edge-deploy.sh` скачивает голос сам при первом запуске.

Поле `voice` в запросе к TTS принимается для совместимости, но звучит всегда Irina. Голос
загружается один раз (в edge-режиме — при первом запросе) и держится в памяти. Кэш WAV чистится
от файлов старше `TTS_CACHE_MAX_AGE_SECONDS`.

Колёса `piper-tts` для macOS arm64 (проверены 1.3.0–1.8.0) не находят данные
espeak-ng — падает даже штатный CLI `piper`. Локально на Mac используйте
Linux-контейнер; тесты TTS (`services/tts/tests`) подменяют голос и проходят везде.

Пример загрузки во временный контейнер, подключённый к production volume:

```sh
docker run --rm --env-file deploy/.env \
  -v roastbot_models:/models \
  --entrypoint python \
  ghcr.io/OWNER/roastbot-tts:TAG /service/download_models.py
```

Важно: лицензия голоса Irina не подтверждена для этого проекта. До
коммерческого использования самостоятельно найдите и сохраните условия лицензии
конкретных `.onnx` и `.onnx.json`; при сомнении не разворачивайте Irina и
замените `FEMALE_MODEL` на модель с проверенной лицензией.

## Триггеры: на что бот реагирует

Всё настраивается в панели: карточки «Характер», «Чат», «Награда с текстом», «События». Новые
триггеры по умолчанию выключены.

Героини: **Мицуки** (цундэрэ) и **Аи** (яндэрэ). На любой триггер героиня отвечает по смыслу
сообщения и события; просьба «скажи стримеру…» для неё тема для шутки, а не поручение.

- **Кого жарить** — один переключатель на все триггеры: «Автора», «Стримера» или «На усмотрение»
  героини (модель сама решает по смыслу). Если автора нет (анонимный донат, реклама, сообщение
  самого стримера), достаётся стримеру.
- **Награда за баллы** с текстом — героиня читает текст и отвечает по смыслу.
- **Слова-триггеры** — бот сам отвечает на сообщения, где слово стоит в начале любого слова
  («слил» → «слился»), с заданным шансом. Команды на `!` и сообщения ботов (Nightbot,
  StreamElements и др.) пропускаются.
- **`!роаст`** — только на тарифах Basic и Premium (`COMMAND_PLANS`); на Free сервис чата и
  воркер её игнорируют (`command_not_in_plan`). Можно выключить.
- Сохранённые настройки, смену тарифа и одобрение сервис чата применяет сразу (уведомление
  `channels_changed` из базы, миграции 0008–0009).
- **События Twitch (EventSub)**: битсы (порог), подписки и ресабы, подарочные сабы (порог),
  рейды (порог по зрителям), фоллоу (шанс), итоги прогнозов, реклама; донаты DonationAlerts — по
  смыслу их текста. Для событий кулдауны не действуют (кроме фоллоу), квота и все проверки
  модерации — да.

**DonationAlerts.** Подключение, а не способ входа: стример, уже вошедший через Twitch, нажимает
«Подключить» в карточке событий, разрешает доступ и возвращается в панель. Обратный вызов
принимается только в той же сессии RoastBot, которая начала подключение. Токены хранятся
зашифрованными (`donationalerts_accounts`), донаты приходят через Centrifugo DonationAlerts в
сервис `twitch`, порог — в валюте доната, аноним жарит стримера, аудиосообщения без текста.
Нужно приложение на https://www.donationalerts.com/application/clients с Redirect URL
`PUBLIC_URL/integrations/donationalerts/callback` (для roast.recursia.online —
`https://roast.recursia.online/api/integrations/donationalerts/callback`) и его ключи в
`DONATIONALERTS_CLIENT_ID` / `DONATIONALERTS_CLIENT_SECRET`. Без них интеграция скрыта.

**Проверка EventSub без эфира.** Twitch CLI поднимает локальный мок EventSub:
`twitch event websocket start-server`. Запустите сервис `twitch` с
`TWITCH_EVENTSUB_WS_URL=ws://127.0.0.1:8080/ws` и
`TWITCH_EVENTSUB_SUBSCRIPTIONS_URL=http://127.0.0.1:8080/eventsub/subscriptions`, затем шлите
события: `twitch event trigger channel.raid --transport=websocket`. Без переменных сервис
ходит в настоящий Twitch.

Для событий нужны права Twitch: `bits:read`, `channel:read:subscriptions`,
`moderator:read:followers`, `channel:read:predictions`, `channel:read:ads`. Каналы, вошедшие
раньше, видят в панели предложение перезайти; рейды и награда работают и без этого.

**Лёгкая грубость.** На токсичности 4–5 бот может сказать «жопа», «задница», «собака»;
классификатор это пропускает. Мат, слюры и угрозы запрещены на любом уровне, встроенный
стоп-лист работает как прежде.

## Тур для стримера

При первом входе в панель открывается пошаговый тур: что означает каждый блок,
как включить награду за баллы, как подключить оверлей в OBS и как сделать тест.
Тур можно открыть снова кнопкой «Тур» вверху страницы; факт прохождения хранится
в `localStorage` браузера. Тексты шагов — `apps/web/src/tour-steps.ts`; при
переносе элемента в другое место обновите `data-tour` в `apps/web/src/dashboard/`,
иначе тест `apps/web/src/tour.test.ts` упадёт. Ссылка `/?tour=1` открывает тур принудительно.

**Адреса панели** (`apps/web/src/routes.ts`, без библиотеки роутинга): `/admin/<вкладка>`
(`users?search=…`, `roasts?channel=<логин или UUID>&status=…&from=…&to=…`), `/roasts/<id>` —
один роаст (вход, ответ, причина, модель и голос; владельцу — любой канал), `/#reward`,
`/#events`, `/#fine-tuning` — прокрутка к карточке. nginx и Caddy отдают `index.html` на любой
путь, поэтому ссылки переживают перезагрузку.

**Память и контекст.** Перед генерацией воркер смотрит роасты этого зрителя на канале: сколько
за 12 часов и за 30 дней и прошлую реплику героини. Это уходит в промпт данными в `<history>`:
героиня может обыграть «опять ты» и не повторяет шутку. Игру канала сервис `twitch` берёт из
Helix (`GET /channels`, кэш 10 минут на канал) и передаёт в `<game>`; «Just Chatting» не
передаётся, заголовок стрима не берётся. Тест из панели берёт игру так же.

**Демо на лендинге.** Блок «Напишите, что сказал бы зритель»: Аи отвечает без входа, 3 раза в
день на IP и `demo_daily_limit` (по умолчанию 30) на весь сервис, 0 скрывает блок. Пишет модель
попроще тарифа Free, проверки те же (стоп-лист, инъекции, классификатор), голос только Яндекс в
пределах его лимита; без Яндекса ответ приходит текстом, Piper не используется. Отдельная очередь
`demo.requested`, роасты на стриме она не задерживает. Деньги демо входят в месячный бюджет.
IP хранится только как HMAC с датой (`demo_requests.ip_hash`), тексты стираются через сутки.
Адрес клиента Fastify берёт из `X-Forwarded-For` (`trustProxy`): если фронтовый прокси
пропускает заголовок клиента, лимит на IP можно обойти, общий дневной лимит при этом держит.

**Админка** (`apps/web/src/admin/`, файл на вкладку): «Обзор» — что требует внимания, деньги
против лимитов, сегодня; «Пользователи» — заявки, приглашения, тариф со сроком и подарок квоты в
диалогах; «Роасты» и «Модерация» — статусы и причины словами; «Настройки» — kill switch, лимиты,
модели, голоса и тарифы, у каждого блока своя кнопка; «Аудит» — действия словами с фильтром.

**Инвайт-ссылки** (`/admin/users` → «Инвайт-ссылки», миграция 0014). Ссылка
`/i/<код>` пускает нового стримера без заявки и может дать тариф на срок (например, Premium на
30 дней для промо). Владелец задаёт число входов и срок действия, видит, кто вошёл. Ссылка
применяется после входа через Twitch (`/auth/twitch?invite=<код>` → cookie → callback); один
аккаунт использует ссылку один раз, приостановленный аккаунт ссылка не возвращает.

**Telegram-бот для стримера** (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`,
`TELEGRAM_WEBHOOK_SECRET`; без них карточки скрыты). «Подключить Telegram» в панели даёт
одноразовую ссылку `t.me/<бот>?start=<код>` на 10 минут. Бот пишет: квота израсходована на 80% и
закончилась (раз в месяц), Twitch отказал в подписке (раз в день на тип), итог после стрима —
когда канал молчит 45 минут: сколько прозвучало, кому доставалось чаще, лучший роаст. Каждое
уведомление бронируется в `notifications_sent`, поэтому не дублируется. `/stop` в боте отключает.

**Зритель может отказаться.** `!роаст-стоп` в чате: бот не отвечает на его сообщения, команды и
фоллоу, а его донаты, битсы и рейды подкалывают стримера; история зрителя в промпт не идёт.
`!роаст-старт` возвращает. Стример видит список в «Тонкой настройке» и может убрать запись.

**Лучшие роасты.** Звёздочка у прозвучавшего роаста в журнале — «лучший»: он попадает в итог
стрима и в очередь витрины (`/admin/moderation`). Одобренные владельцем показываются на
лендинге без ника зрителя, с названием канала; их ответ не стирается по сроку хранения (вход
стирается). Снятая звёздочка убирает роаст с сайта.

**Оплата звёздами Telegram.** Карточка «Тариф» в панели открывает счёт в боте: подписка на 30
дней, продлевается автоматически, отменяется в Telegram. Telegram спрашивает подтверждение
(`pre_checkout_query`: канал активен, цена совпадает), затем присылает `successful_payment` —
при первой оплате и при каждом продлении; каждый платёж (по `telegram_payment_charge_id`, один
раз) добавляет подписку до даты, которую назвал Telegram. Возврат во вкладке «Платежи»
отменяет продления и сразу заканчивает тариф. Деньги выводятся через Fragment в TON: от 1000 ⭐
и через 21 день, около $0,013 за звезду, после обмена ≈ $0,0124.

Цены по минимуму — окупаемость при полном расходе квоты:

|                                            | Роаст стоит | Basic: 300 в месяц | Premium: 1500 в месяц |
| ------------------------------------------ | ----------- | ------------------ | --------------------- |
| Лучшая связка (Opus + ElevenLabs)          | ≈ $0,02     | 50 → $1            | 300 → $6              |
| Попроще (Haiku + Sonnet-проверка + Яндекс) | ≈ $0,004    | 250 → $1           | 1200 → $4,8           |
| Итого расход                               |             | $2                 | $10,8                 |
| Нужно звёзд (/ $0,0124)                    |             | 161 → **170 ⭐**   | 871 → **900 ⭐**      |

Цена и число лучших роастов меняются в `/admin/settings` → «Тарифы», число роастов в месяц —
в `packages/db/src/seed.ts` (seed обновляет его при деплое; миграция 0015 перевела тарифы
с 1000/5000 роастов за 600/3000 ⭐ на эти). Реальный расход обычно
ниже лимита, так что запас идёт в прибыль. Месячный бюджет Anthropic (`monthly_budget_usd`) и
лимит ElevenLabs нужно поднимать вместе с числом платных каналов: 70 000 символов ElevenLabs —
это примерно 700 лучших роастов на весь сервис, дальше голос сам переходит на Яндекс.

**Подпись на оверлее.** На тарифе Free (`BRANDED_PLANS`) под карточкой роаста мелко видно адрес
сервиса (хост страницы оверлея); на платных её нет.

## OBS

1. Войдите в панель, откройте настройки канала и скопируйте полную overlay-ссылку.
2. OBS → Sources → `+` → Browser, вставьте URL, задайте 1920×1080.
3. Включите `Control audio via OBS`, направьте звук в нужную дорожку.

Рядом с текстом появляется персонаж выбранного тона (цундэрэ или яндэрэ) и «говорит», пока
звучит озвучка. Чтобы выставить источник до эфира, откройте в OBS
`https://APP_DOMAIN/overlay/?preview=tsundere` (или `yandere`): это пример карточки без токена
и без подключения. Картинки лежат в `apps/overlay/src/assets/`, исходники и скрипт вырезания
фона — в `assets/source/` и `apps/overlay/scripts/cutout.py`.

Не публикуйте overlay URL: query-параметр содержит секретный токен. Если ссылка
утекла, нажмите «Перевыпустить ссылку» в панели: старый токен перестаёт
работать, открытые оверлеи отключаются.
В OBS звук играет сам: Browser Source разрешает автовоспроизведение, и кнопок на оверлее там
не бывает. В обычной вкладке браузера (например, для проверки) браузер требует один клик:
оверлей сразу просит нажать «включить звук», дальше до перезагрузки всё играет само. Если звук
так и не заиграл, карточка показывается как текст на время чтения и уходит — очередь не
застревает.

## Владельцы и admin

`TWITCH_OWNER_IDS` — числовой Twitch user ID **владельца сервиса** (ваш), а не
стримеров; несколько через запятую. Это не логин. Узнать ID можно через Twitch
Helix `/users` с app/user token. Роль вычисляется при OAuth-входе; после изменения
списка владельцу нужно выйти и войти снова. Не назначайте владельцем общий
аккаунт и защищайте Twitch-аккаунт MFA. Ключ Anthropic тоже только ваш: он лежит
в `.env` сервера, стримеры его не видят и не вводят.

## Регистрация стримеров

Регистрация ручная. Стример входит через Twitch и получает статус «заявка»: панель
показывает «Ждём одобрения», бот на его канале не работает, ссылка оверлея не
выдаётся. В `/admin` → «Пользователи» заявки стоят первыми, кнопки «Одобрить» и
«Отклонить»; на «Обзоре» есть счётчик заявок. Второй способ — «Приглашения»: впишите
логин Twitch заранее, и этот логин войдёт без заявки (одноразово). Если стример
уже ждёт, приглашение одобряет его сразу. Все шаги пишутся в «Аудит»
(`user.signup`, `invite.create`, `user.activate`).

## Двухфакторная аутентификация

Вход — Twitch OAuth плюс TOTP-код (Google Authenticator, 1Password, Bitwarden).

- Владельцу 2FA **обязательна**: без неё `/admin` показывает мастер настройки, а
  все `/admin/*` отвечают `403 mfa_setup_required`. Код подтверждается при каждом
  входе через Twitch и повторно раз в 12 часов для админки. Отключить 2FA владельцу
  нельзя.
- Стримеру 2FA по желанию: «Включить 2FA» в шапке панели. Если включена, без кода
  после входа доступны только экран ввода кода и выход.
- При включении выдаются 8 одноразовых резервных кодов; их можно перевыпустить на
  странице «Безопасность».
- 5 неверных кодов подряд блокируют проверку на 15 минут; уже использованный код
  повторно не принимается.
- Секрет TOTP шифруется `TOKEN_ENCRYPTION_KEY`, резервные коды хранятся только как
  SHA-256.
- Стримеру, потерявшему телефон и коды, владелец сбрасывает 2FA в «Пользователях»
  («Сбросить 2FA»). Свою 2FA из интерфейса сбросить нельзя — это аварийная
  операция с доступом к серверу:

```sh
docker compose --env-file deploy/.env -f deploy/docker-compose.yml exec postgres \
  psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "update users set
  totp_secret_ciphertext=null, totp_secret_iv=null, totp_secret_tag=null,
  totp_enabled_at=null, totp_last_step=null, mfa_recovery_hashes='{}',
  mfa_failed_attempts=0, mfa_locked_until=null where twitch_id='ВАШ_TWITCH_ID'"
```

## Переменные окружения

Полный исполняемый шаблон находится в `deploy/.env.example`.

- Домены: `APP_DOMAIN`, `API_DOMAIN`, `ACME_EMAIL`; URL со схемой:
  `PUBLIC_URL`, `DASHBOARD_URL`, `TWITCH_REDIRECT_URI`.
- Образы: `GHCR_OWNER`, `IMAGE_TAG`.
- PostgreSQL: `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`,
  `DATABASE_URL`. Пароль внутри URL должен быть percent-encoded.
- Twitch: `TWITCH_CLIENT_ID`, `TWITCH_CLIENT_SECRET`, `TWITCH_OWNER_IDS`.
- Секреты: `SESSION_SECRET`, `AUDIO_SIGNING_SECRET`,
  `TOKEN_ENCRYPTION_KEY`.
- Anthropic: `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL`.
- Piper: `FEMALE_MODEL`, `TTS_CACHE_MAX_AGE_SECONDS`.
- Backup: `BACKUP_DIR`, `BACKUP_RETENTION_DAYS`, `BACKUP_EXTERNAL_HOOK`.
- Existing proxy: `API_HOST_PORT`, `WEB_HOST_PORT`, `OVERLAY_HOST_PORT`.

`TOKEN_ENCRYPTION_KEY` — master key AES-256: ровно 32 случайных байта в виде
64 hex-символов (`openssl rand -hex 32`). Это не base64. Отдельной переменной
`MASTER_ENCRYPTION_KEY` код не читает. Не меняйте ключ после подключения
каналов: существующие Twitch-токены перестанут расшифровываться.
`SESSION_SECRET` и `AUDIO_SIGNING_SECRET` создаются независимо, например
`openssl rand -base64 48`.

Опциональный ежедневный Telegram-отчёт включается только если одновременно
заданы `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Worker отправляет отчёт в
09:00 по timezone контейнера (по умолчанию UTC). Оставьте обе переменные пустыми,
чтобы функцию отключить. С `DASHBOARD_URL` в отчёте есть ссылки на ошибки и очередь модерации.

## Миграции и seed

Вручную локально:

```sh
DATABASE_URL=postgresql://... pnpm db:migrate
DATABASE_URL=postgresql://... ANTHROPIC_MODEL=claude-opus-5-5 pnpm db:seed
```

Мигратор использует одну PostgreSQL-сессию и advisory lock, поэтому параллельные
деплои не применят миграции одновременно. Seed использует upsert/on-conflict и
может выполняться повторно. Никогда не генерируйте миграцию прямо на production;
сначала создайте и проверьте SQL в отдельной БД.

## Тесты

```sh
pnpm build          # сначала: тесты и type-aware lint читают workspace-пакеты из dist/
pnpm format:check
pnpm lint
pnpm test           # unit + интеграционные тесты на настоящем PostgreSQL 16
cd services/tts && python -m unittest discover -s tests -t .
```

Интеграционные тесты (`*.integration.test.ts`) поднимают одноразовый кластер
PostgreSQL 16 через `embedded-postgres` (`packages/testing`), применяют миграции
и seed и проверяют реальный SQL: квоты и подарки, кулдауны, kill switch и
денежный лимит, модерацию, outbox оверлея по WebSocket с подписанным аудио,
admin API и очередь pg-boss. Docker для них не нужен. Anthropic и TTS в тестах
подменяются.

GitHub Actions повторяет эти команды, затем собирает шесть production-образов.
На PR образы только собираются; на `main` публикуются в GHCR с тегами SHA и
`latest`. SSH deploy выполняется только для push в `main` и только когда заданы
secrets `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_SSH_KEY`, `DEPLOY_PATH`,
`GHCR_USER`, `GHCR_READ_TOKEN`. На сервере уже должны быть репозиторий и
заполненный `deploy/.env`.

## Сервер с общим Caddy (edge-режим): roast.recursia.online

Так RoastBot живёт на одном VPS с Purrse и IT Connect: порты 80/443 и TLS держит Caddy
из `purrse-web`, проекты общаются через Docker-сеть `edge`. RoastBot ничего не публикует на
хосте; его Caddy называется `roastbot-edge` и слушает `:8080` внутри `edge`. Файлы:
`deploy/docker-compose.edge.yml`, `deploy/Caddyfile.edge`, `deploy/edge-deploy.sh`.
Образы готовые: GitHub Actions собирает их на каждый push в `main` и публикует в GHCR, а
сервер скачивает образы ровно того коммита, который у него в checkout. Сборка на сервере
осталась запасным путём (`BUILD=1`, по одному образу — параллельная не помещается в 2 ГБ).
CI собирает под x86_64; на сервере с другим процессором скрипт останавливается и предлагает
`BUILD=1`.

Замер на копии стека: в работе около 380 МиБ RAM вместе с загруженным голосом, сборка
шести образов — около 100 с на Mac (на 1 vCPU сервера ожидаемо в несколько раз дольше),
синтез фразы — 1–2 с при лимите в 1 CPU.

**Один раз:**

1. DNS: A-запись `roast` для `recursia.online` на IP сервера.
2. Twitch Developer Console: добавьте OAuth Redirect URL
   `https://roast.recursia.online/api/auth/twitch/callback`.
3. Доступ сервера к репозиторию — deploy key только на чтение:

   ```sh
   ssh-keygen -t ed25519 -N "" -C roastbot-deploy -f ~/.ssh/roastbot_deploy
   cat ~/.ssh/roastbot_deploy.pub   # GitHub → репозиторий → Settings → Deploy keys,
                                    # «Allow write access» не включать
   cat >> ~/.ssh/config <<'EOF'
   Host github-roastbot
     HostName github.com
     IdentityFile ~/.ssh/roastbot_deploy
     IdentitiesOnly yes
   EOF
   git clone git@github-roastbot:Degsteroz/twitch_speaker_bot.git /opt/roastbot
   ```

   Чтение образов из GHCR: GitHub → Settings → Developer settings → Personal access tokens →
   classic, только `read:packages`. На сервере один раз:

   ```sh
   docker login ghcr.io -u degsteroz   # пароль — этот токен
   ```

4. `cp deploy/.env.example deploy/.env && chmod 600 deploy/.env` и заполните по
   комментарию в начале файла, `GHCR_OWNER=degsteroz` — строчными. Все секреты генерируйте на сервере заново, не берите из
   локального `.env`.
5. В Caddyfile Purrse (`/opt/purrse/deploy/Caddyfile`) добавьте блок и пересоберите его
   `web` (сайты Purrse и IT Connect недоступны несколько секунд):

   ```caddyfile
   roast.recursia.online {
   	encode gzip
   	reverse_proxy roastbot-edge:8080
   }
   ```

   ```sh
   cd /opt/purrse && docker compose up -d --build web
   ```

**Запуск и каждое обновление:**

```sh
cd /opt/roastbot && ./deploy/edge-deploy.sh
```

Скрипт делает `git pull --ff-only`, скачивает образы этого коммита из GHCR (сначала дождитесь
зелёного CI в Actions; без него скрипт скажет, что образов ещё нет), при первом запуске скачивает
голоса Piper с проверкой SHA-256 и поднимает стек; `migrate` применяет миграции до старта
сервисов. Проверка: `https://roast.recursia.online/health` и `/api/ready`.

`backup.sh` и `restore.sh` сами узнают edge-режим по контейнеру `roastbot-edge`.

## Production и существующий reverse proxy

Встроенный Caddy автоматически получает сертификаты для обоих доменов и
пересылает WebSocket без отдельной директивы. Не запускайте его, если 80/443 уже
заняты Caddy, Nginx или Traefik.

Для существующего host proxy:

```sh
docker compose --env-file deploy/.env \
  -f deploy/docker-compose.yml \
  -f deploy/docker-compose.existing-proxy.yml \
  up -d postgres migrate api worker twitch tts web overlay
```

На `APP_DOMAIN` отправляйте `/api/*` на `127.0.0.1:3000` со снятием `/api`,
WebSocket `/overlay/TOKEN` — на тот же API без снятия префикса, `/overlay/` —
на `127.0.0.1:8081` со снятием `/overlay`, остальные запросы — на
`127.0.0.1:8080`. `API_DOMAIN` можно направить прямо на `127.0.0.1:3000` для
отдельного health endpoint. Включите HTTPS и Upgrade/Connection для WebSocket.
Loopback-порты можно изменить в `.env`; Caddy этой командой не запускается.

## Backup и restore

```sh
./deploy/backup.sh
ROASTBOT_RESTORE_CONFIRM=restore-production \
  ./deploy/restore.sh deploy/backups/roastbot-YYYYMMDDTHHMMSSZ.dump
```

Backup использует custom/compressed `pg_dump`, атомарно переименовывает готовый
файл и удаляет архивы старше 7 дней. Для внешней копии задайте путь к
исполняемому `BACKUP_EXTERNAL_HOOK`; он получает путь архива первым аргументом.
Например, hook может выполнять `rclone copy "$1" remote:roastbot/`. Проверяйте
restore на отдельном окружении регулярно.

Расписание на сервере (`crontab -e`), бэкап каждую ночь:

```cron
30 4 * * * cd /opt/roastbot && ./deploy/backup.sh >> deploy/backups/backup.log 2>&1
```

Копия вне сервера — на Mac: `./deploy/mac/install-backup-pull.sh user@host`. Mac каждый день в
5:30 забирает архивы по SSH в `~/Backups/roastbot` (30 дней), уведомляет, если забрать не вышло
или свежих архивов нет двое суток. Лог — `~/Library/Logs/roastbot-backup.log`. Без
`TOKEN_ENCRYPTION_KEY` из `deploy/.env` токены Twitch из архива не расшифруются: храните копию
`.env` отдельно, например в менеджере паролей.

Restore требует явного guard, проверяет каталог архива через `pg_restore`,
останавливает API/worker/Twitch, восстанавливает архив в отдельную базу `<db>_restore` и
только после полного успеха подменяет ею рабочую. Прежняя база остаётся как
`<db>_previous` до следующего restore; при ошибке рабочая база не тронута. `pg_restore
--clean` поверх рабочей базы не используется: на секционированных таблицах pg-boss он
падает на середине и оставляет схему без индексов.

## Health и мониторинг

- API liveness: `https://APP_DOMAIN/health` (также `/api/health` и `https://API_DOMAIN/health`).
- API readiness: `https://APP_DOMAIN/api/ready` (или `https://API_DOMAIN/ready`).
- Внутренний TTS `/health` сообщает наличие обеих моделей.
- Состояние: `docker compose ... ps`.
- Логи: `docker compose ... logs -f --since=10m api worker twitch tts`.

Настройте внешний uptime-check на `/ready`. Docker-логи ограничены тремя файлами
по 10 МиБ на контейнер. Для расследования ошибок сопоставляйте API/worker логи с
таблицами `roasts` и `audit_log`; не отправляйте секреты и полный `.env` в
систему мониторинга.

## Модерация и защита от инъекций

Каждый запрос проходит слои по порядку; первый сработавший останавливает роаст.

1. **Ник** сверяется со всем встроенным списком (`packages/prompts/src/blocklist.ts`): его
   читают вслух. **Сообщение** — только с «никогда»-категориями (`ALWAYS_BLOCKED`): этнические,
   гомофобные и эйблистские оскорбления, самоповреждение, нацистские лозунги, 14/88 и свастики.
   Мат, пошлость и «дебил» от зрителя не глушат бота: героиня отвечает, не повторяя их. Перед сравнением текст нормализуется: регистр, `ё`, латинские и цифровые
   двойники (`пuд0р`), транслит (`pidor`, `nahuy`), leetspeak (`n1gg3r`), разбивка (`п и д о р`,
   `пи-дор`), маски (`п*дор`), повторы букв, приставки (`заебал`, `нахуй`), склеенные ники
   (`HeilHitler88`). Встроенный список отключить нельзя; слова из `/admin` и канала дополняют его.
2. **Попытка инъекции** («игнорируй инструкции», «повтори дословно», «ты теперь…», теги)
   отклоняется сразу: роаст-боту не нужно выполнять команды из чата. Квота и деньги не тратятся.
3. **Генерация**: правила только в системном промпте, ник и сообщение — экранированные данные в
   тегах, сообщение обрезается до 300 символов.
4. **Ответ** снова проходит список (`outputBlockedCategories`): оскорбления, экстремизм,
   самоповреждение и сексуальное унижение — всегда; грубые оскорбления («дебил») — до
   токсичности 3; мат — до токсичности 4 (на 5 «Без пощады» разрешён). Затем проверка на ссылки
   и контакты, утечку промпта и дословный повтор шести и более слов из сообщения зрителя.
5. **Классификатор** (по умолчанию Sonnet 5.5) получает ответ в теге `<reply>` и ищет вред, а не
   грубость: роаст должен колоть, а «жуть» яндэрэ — часть роли. Всё, кроме `ALLOW`, — блок.

Заблокированный ответ заменяется заглушкой и попадает в «Модерацию» в `/admin`. Известные
ложные срабатывания, оставленные ради надёжности: страна Нигер, фамилия Huynh.

## Безопасность и retention

- Все секреты храните только в `deploy/.env` с правами `chmod 600`; файл
  исключён из Docker build context.
- GHCR read token должен иметь только `read:packages`, deploy SSH key — отдельный
  непривилегированный пользователь с минимальным доступом к Docker.
- PostgreSQL, API и внутренние сервисы не публикуют порты в стандартном compose.
- OAuth state, HttpOnly/Secure cookie, шифрование Twitch-токенов и подписанные
  одноразовые по времени аудиоссылки уже включены.
- Worker каждые 10 минут обнуляет текст входа/выхода и сырые события чата
  (`events.raw`) старше 30 дней, чистит просроченный outbox и cooldown-записи и
  удаляет WAV старше 10 минут. Аудиоссылка подписывается в момент доставки в
  overlay и живёт 60 секунд.
- Backup хранится 7 дней по умолчанию. Внешнее хранилище должно иметь шифрование,
  отдельную retention-политику и проверенное удаление.
- Ограничьте firewall портами SSH/80/443, обновляйте host и образы, включите MFA
  в Twitch, GitHub и Anthropic.

## Диагностика

- `migrate` завершился с ошибкой: смотрите `docker compose ... logs migrate`;
  проверьте `DATABASE_URL`, доступность PostgreSQL и SQL миграции.
- TTS unhealthy: в volume нет `.onnx` или соседнего `.onnx.json`, имя не
  совпадает с `FEMALE_MODEL`, либо volume недоступен для чтения.
- OAuth `redirect_mismatch`: callback в Twitch Console и
  `TWITCH_REDIRECT_URI` отличаются хотя бы одним символом.
- Бесконечный OAuth/нет cookie: проверьте HTTPS, `APP_DOMAIN`, системное время и
  что callback приходит прямо в API.
- Overlay не подключается: проверьте полный URL с token, сертификат API и
  WebSocket proxy; в OBS обновите Browser Source cache.
- Нет звука: проверьте TTS health, модели, `worker` logs и настройки аудио OBS.
- Нет наград: в панели стримера карточка статуса и «Журнал» показывают, открыт ли оверлей,
  принял ли Twitch подписку на награду (`eventsub_state`) и чем закончилось каждое событие
  (пауза, стоп-лист, квота, истёкший оверлей). Красный крестик у награды — перезайдите через
  Twitch и проверьте `twitch` logs.
- `401` после ротации ключа: верните прежний `TOKEN_ENCRYPTION_KEY` либо
  переподключите все каналы.
- 80/443 заняты: не убивайте чужой proxy; используйте existing-proxy вариант.
