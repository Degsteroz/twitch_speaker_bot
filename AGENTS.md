# AGENTS.md — руководство для агента

Этот файл для агента (Claude Code и подобных), который открывает репозиторий
RoastBot впервые или на новой машине. Читайте его целиком до первой правки.
Пользовательская документация — в [README.md](README.md). Продуктовый план и
требования — в [RoastBot-PLAN.md](RoastBot-PLAN.md).

---

## 1. Что это за проект

RoastBot — Twitch-сервис: зритель пишет `!роаст` в чат или активирует награду
за баллы, бот генерирует короткий язвительный ответ через Claude Haiku, озвучивает
его локально (Piper) и отправляет в OBS Browser Source.

Компоненты (`services/`, `apps/`, `packages/`):

| Путь               | Что делает                                                          |
| ------------------ | ------------------------------------------------------------------- |
| `services/api`     | Fastify: OAuth Twitch, REST для панели, WebSocket оверлея, `/admin` |
| `services/worker`  | pg-boss: генерация, модерация, квоты, TTS, outbox оверлея, очистка  |
| `services/twitch`  | tmi.js (чат) и EventSub WebSocket (награды)                         |
| `services/tts`     | FastAPI над Piper, `POST /synth` → WAV                              |
| `apps/web`         | React + Vite: панель стримера, `/admin`, тур                        |
| `apps/overlay`     | Страница для OBS Browser Source                                     |
| `packages/db`      | Схема Drizzle, миграции, seed, очистка данных                       |
| `packages/shared`  | zod-схемы, константы, типы событий                                  |
| `packages/prompts` | Промпты, стоп-лист, оценка стоимости, классификатор                 |
| `packages/testing` | Одноразовый PostgreSQL 16 для интеграционных тестов                 |
| `deploy/`          | docker-compose, Caddy, скрипты backup/restore/preflight             |
| `scripts/demo.mjs` | Локальный демо-стенд без Docker и Twitch                            |

## 2. Требования к окружению

- Node.js 20+ (CI и образы — Node 22), pnpm 10.18.3 (`corepack enable`)
- Python 3.12 — только для `services/tts`
- Docker Desktop / Engine — для продакшен-сборки и compose (необязательно для разработки)
- macOS arm64 или Linux x86_64 (см. раздел «Известные ограничения»)

Первый запуск:

```sh
pnpm install --frozen-lockfile
pnpm build            # обязательно до lint/test: тесты читают workspace-пакеты из dist/
pnpm test
pnpm lint
pnpm format:check
```

Ожидаемый результат на момент передачи: `pnpm test` — 207 тестов проходят;
`pnpm lint` и `pnpm format:check` — без ошибок.

Python-тесты TTS:

```sh
cd services/tts
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt httpx
python -m unittest discover -s tests -t .
```

## 3. Секреты и конфигурация

- Секреты **никогда не коммитятся**. В git попадают только шаблоны:
  `.env.example` (локальная разработка) и `deploy/.env.example` (прод).
- Перед первым запуском создайте `.env` в корне: `cp .env.example .env`.
- `.env` читают dev-скрипты через `tsx --env-file=../../.env`
  (`api`, `worker`, `twitch`, `packages/db`).
- Для прода: `deploy/.env`, права `600`, в Docker Compose через `--env-file`.
- Никогда не вставляйте реальные ключи в код, тесты, README, коммит-сообщения
  или вывод команд. Тесты используют фиктивные значения.
- `TOKEN_ENCRYPTION_KEY` — ровно 64 hex-символа. После подключения каналов его
  менять нельзя: токены Twitch перестанут расшифровываться.

Проверка перед коммитом (ручная, пока нет pre-commit хука):

```sh
git grep --cached -nE "sk-ant-|ghp_|xox[bp]-|AKIA[0-9A-Z]{12}|-----BEGIN"
```

Пустой вывод — ок.

## 4. Локальная разработка

Вариант А — демо без внешних сервисов (рекомендуется для первого знакомства):

```sh
pnpm demo                      # фейковые ответы модели, macOS say вместо Piper
ANTHROPIC_API_KEY=… pnpm demo  # настоящий Haiku (или ключ из корневого .env)
```

Адреса: вход без Twitch `http://localhost:5175/login`, панель
`http://localhost:5173`, оверлей `http://localhost:5174/overlay/?token=demo-overlay-token`.
Остановка — Ctrl+C; скрипт завершает все дочерние процессы по группе.

Вариант Б — отдельные сервисы (нужны PostgreSQL 16 и `.env`):

```sh
pnpm db:migrate && pnpm db:seed
pnpm --filter @roastbot/api dev
pnpm --filter @roastbot/worker dev
pnpm --filter @roastbot/twitch dev
pnpm --filter @roastbot/web dev
pnpm --filter @roastbot/overlay dev
```

## 5. Тесты: что покрыто и что нет

| Вид            | Где                        | Что проверяет                                                                                                        |
| -------------- | -------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| Unit           | `packages/*/src/*.test.ts` | стоп-лист, нормализация, стоимость, промпт, классификатор                                                            |
| Интеграционные | `*.integration.test.ts`    | реальный PostgreSQL: квоты, кулдауны, kill switch, бюджет, модерация, outbox и WebSocket оверлея, admin API, pg-boss |
| Web            | `apps/web/src/*.test.ts`   | нормализация настроек, URL оверлея, тур (ссылки на `data-tour`)                                                      |
| Python         | `services/tts/tests`       | HTTP-контракт TTS с подменённым голосом                                                                              |

Не покрыто автотестами: реальные Twitch, Anthropic, Piper, сборка Docker-образов,
внешний вид интерфейса. Их проверяют вручную (см. раздел 8).

Интеграционные тесты поднимают одноразовый кластер через `embedded-postgres`.
Docker для них не нужен. Anthropic и TTS в тестах заменены фейками.

## 6. Правила работы с репозиторием

- **Не коммитьте без явной просьбы пользователя.** Не делайте `git add`, `commit`
  или `push` сами. Если коммит кажется полезным, предложите его одной строкой.
- Формат коммит-сообщения: `TYPE(APP): CHANGES`, например
  `feat(worker): add monthly TTS character limit`. Типы: `feat`, `fix`, `docs`,
  `refactor`, `test`, `chore`, `ci`.
- Текущее состояние: `git init` сделан, коммитов нет, все файлы не в индексе.
- Перед правкой миграций: существующие миграции не редактируются. Новые
  добавляются файлом `NNNN_name.sql` и записью в `packages/db/migrations/meta/_journal.json`.
- Перед изменением публичного контракта (zod-схемы в `packages/shared`) проверьте
  все места использования: `grep -rn "<имя>" services apps packages`.

## 7. Ключевые инварианты (не ломать)

1. **Блок безопасности первый в промпте** (`SAFETY_BLOCK`). Тон и токсичность
   меняют только стиль, не границы.
2. **Ник, вход и выход проходят встроенный стоп-лист** (`packages/prompts/src/blocklist.ts`,
   отключить нельзя; admin- и канальные слова только добавляются). Нормализация ловит транслит,
   leetspeak, омоглифы, разбивку и маски. Вход с попыткой инъекции отклоняется до вызова API.
   Выход дополнительно проверяют на ссылки, утечку промпта и дословный повтор входа, затем
   классификатор Haiku; любой ответ кроме `ALLOW` блокируется (fail-closed). Инструкции идут
   только в `system`, данные зрителя — только в user-сообщение, экранированные и в тегах.
   Новое слово в списке — с примером в `MUST_BLOCK`, а если есть риск коллизии, и в `MUST_ALLOW`
   (`packages/prompts/src/index.test.ts`).
3. **Модель вызывается с `thinking: {type: "disabled"}` и без `temperature`.**
   Haiku 5.5 отклоняет `temperature` с 400 и по умолчанию думает, что съедает `max_tokens`.
4. **Квоты и бюджет проверяются до вызова API** в транзакции под advisory lock
   (`reserve()` в `services/worker/src/pipeline.ts`). Стоимость записывается и при успехе,
   и при сбое после вызова Anthropic.
5. **Повторно доставленная задача не тратит квоту.** Если роаст уже не `queued`,
   воркер возвращает его статус без работы.
6. **Очередь без ретраев** (`retryLimit: 0`): роаст старше TTL оверлея не имеет смысла.
7. **Аудиоссылка подписывается в момент доставки** (`signedAudioUrl` в API), а не в воркере.
8. **Оверлейные токены сравниваются через БД.** Перевыпуск токена закрывает открытые сокеты.
9. **Владелец проверяется по БД** (`requireOwner`), а не по JWT.
10. **Cookie сессии `HttpOnly`**, в проде `Secure`.
11. **Регистрация ручная.** Новый вход через Twitch создаёт пользователя в `pending`;
    активным его делает только владелец (одобрение или приглашение по логину в `invites`)
    либо `TWITCH_OWNER_IDS`. `requireUser` отвечает `403 pending_approval`, `/me/session`
    не отдаёт `overlayToken` до одобрения.
12. **2FA (TOTP, `services/api/src/totp.ts`).** Владельцу обязательна: `requireOwner`
    требует `totp_enabled_at` и `mfaAt` в JWT не старше 12 часов. Новый вход через Twitch
    никогда не несёт `mfaAt`. Проверка кода — под `for update`, 5 ошибок блокируют на
    15 минут, принятый шаг не принимается повторно, резервные коды — только SHA-256.
    Свою 2FA владелец не отключает и не сбрасывает из UI.

## 9. Известные ограничения и открытые вопросы

1. **`monthly_tts_limit` не enforce-ится.** Значения в `plans` (20 000 / 200 000 /
   1 000 000 символов) хранятся, `tts_chars` считается, но лимит нигде не проверяется.
   Нужно решение: проверять в `reserve()` или убрать поле до тарифов.
2. **Piper не запускается на macOS arm64** (колёса 1.3.0–1.8.0 не находят
   espeak-ng data). Для Linux-контейнера это не проблема, но локально TTS
   проверяется только через `say` в демо.
3. **Лицензии голосов Piper** (`ru_RU-irina-medium`, `ru_RU-denis-medium`) не
   подтверждены для коммерции. Проверьте карточки на Hugging Face до беты.
4. **Тур**: тексты написаны, но не проверены глазами на реальной вёрстке
   (desktop и телефон).
5. **Лимит $5 в консоли Anthropic** владелец задаёт сам. Приложение дополняет его,
   но не заменяет.
6. **Порядок сборки.** `pnpm test` без предварительного `pnpm build` может падать
   из-за отсутствующих `dist/` у workspace-пакетов.

## 10. Чек-лист для нового агента (первый час)

1. Прочитайте этот файл и [README.md](README.md).
2. `pnpm install --frozen-lockfile && pnpm build && pnpm test && pnpm lint`.
3. `pnpm demo` и пройдите вход → панель → тест-роаст → оверлей. Остановите Ctrl+C.
4. Посмотрите `git status`. Если изменений нет — переходите к задаче.
5. Перед любым изменением спросите себя: затрагивает ли оно инварианты из раздела 7?
   Если да — добавьте или обновите тест.
6. Не коммитьте, пока пользователь не попросил.
