# AGENTS.md — руководство для агента

Этот файл для агента (Claude Code и подобных), который открывает репозиторий
RoastBot впервые или на новой машине. Читайте его целиком до первой правки.
Пользовательская и эксплуатационная документация — в [README.md](README.md). Исходный план v1,
передача контекста и старое задание по оптимизации лежат в [docs/archive/](docs/archive/): это
история, а не текущие требования; при расхождении верен код, этот файл и README.

---

## 1. Что это за проект

RoastBot — Twitch-сервис: зритель активирует награду за баллы, пишет `!роаст` или слово-триггер в
чат, присылает донат или устраивает событие канала, а бот генерирует короткий язвительный ответ
через Claude (модель по тарифу), озвучивает его облачным голосом (ElevenLabs → Inworld → Yandex,
аварийно — Piper) и отправляет в OBS Browser Source.

Компоненты (`services/`, `apps/`, `packages/`):

| Путь               | Что делает                                                                                                   |
| ------------------ | ------------------------------------------------------------------------------------------------------------ |
| `services/api`     | Fastify: OAuth Twitch, REST для панели, WebSocket оверлея, `/admin` (`app.ts` — сборка, маршруты по модулям) |
| `services/worker`  | pg-boss: генерация (`pipeline`), лимиты (`limits`), заглушки (`stubs`), TTS, outbox оверлея, очистка         |
| `services/twitch`  | tmi.js (чат, JOIN через `JoinQueue`) и EventSub WebSocket (награды)                                          |
| `services/tts`     | FastAPI над Piper (аварийный голос), `POST /synth` → WAV                                                     |
| `apps/web`         | React + Vite: панель, `/admin` (`src/admin/`, файл на вкладку), тур                                          |
| `apps/overlay`     | Страница для OBS Browser Source                                                                              |
| `packages/db`      | Схема Drizzle, миграции, seed, очистка данных                                                                |
| `packages/shared`  | zod-схемы, константы, типы событий                                                                           |
| `packages/prompts` | Промпты, стоп-лист, оценка стоимости, классификатор                                                          |
| `packages/testing` | Одноразовый PostgreSQL 16 для интеграционных тестов                                                          |
| `deploy/`          | docker-compose, Caddy, скрипты backup/restore/preflight                                                      |
| `scripts/demo.mjs` | Локальный демо-стенд без Docker и Twitch                                                                     |

## 2. Требования к окружению

- Node.js 20+ (CI и образы — Node 22), pnpm 10.18.3 (`corepack enable`)
- Python 3.12 — только для `services/tts`
- Docker Desktop / Engine — для продакшен-сборки и compose (необязательно для разработки)
- macOS arm64 или Linux x86_64 (см. раздел «Известные ограничения»)

Первый запуск:

```sh
pnpm install --frozen-lockfile
pnpm build            # обязательно до lint/test: тесты читают workspace-пакеты из dist/
pnpm test
pnpm lint
pnpm format:check
```

Ожидаемый результат: `pnpm test` — 402 теста проходят;
`pnpm lint` и `pnpm format:check` — без ошибок.

Python-тесты TTS:

```sh
cd services/tts
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt httpx
python -m unittest discover -s tests -t .
```

## 3. Секреты и конфигурация

- Секреты **никогда не коммитятся**. В git попадают только шаблоны:
  `.env.example` (локальная разработка) и `deploy/.env.example` (прод).
- Перед первым запуском создайте `.env` в корне: `cp .env.example .env`.
- `.env` читают dev-скрипты через `tsx --env-file=../../.env`
  (`api`, `worker`, `twitch`, `packages/db`).
- Для прода: `deploy/.env`, права `600`, в Docker Compose через `--env-file`.
- Никогда не вставляйте реальные ключи в код, тесты, README, коммит-сообщения
  или вывод команд. Тесты используют фиктивные значения.
- `TOKEN_ENCRYPTION_KEY` — ровно 64 hex-символа. После подключения каналов его
  менять нельзя: токены Twitch перестанут расшифровываться.

Проверка перед коммитом (ручная, пока нет pre-commit хука):

```sh
git grep --cached -nE "sk-ant-|ghp_|xox[bp]-|AKIA[0-9A-Z]{12}|-----BEGIN"
```

Пустой вывод — ок.

## 4. Локальная разработка

Вариант А — демо без внешних сервисов (рекомендуется для первого знакомства):

```sh
pnpm demo                      # фейковые ответы модели, macOS say вместо Piper
ANTHROPIC_API_KEY=… pnpm demo  # настоящий Anthropic (или ключ из корневого .env)
```

Адреса: вход без Twitch `http://localhost:5175/login`, панель
`http://localhost:5173`, оверлей `http://localhost:5174/overlay/?token=demo-overlay-token`.
Остановка — Ctrl+C; скрипт завершает все дочерние процессы по группе.

Вариант Б — отдельные сервисы (нужны PostgreSQL 16 и `.env`):

```sh
pnpm db:migrate && pnpm db:seed
pnpm --filter @roastbot/api dev
pnpm --filter @roastbot/worker dev
pnpm --filter @roastbot/twitch dev
pnpm --filter @roastbot/web dev
pnpm --filter @roastbot/overlay dev
```

## 5. Тесты: что покрыто и что нет

| Вид            | Где                        | Что проверяет                                                                                                        |
| -------------- | -------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| Unit           | `packages/*/src/*.test.ts` | стоп-лист, нормализация, стоимость, промпт, классификатор                                                            |
| Интеграционные | `*.integration.test.ts`    | реальный PostgreSQL: квоты, кулдауны, kill switch, бюджет, модерация, outbox и WebSocket оверлея, admin API, pg-boss |
| Web            | `apps/web/src/*.test.ts`   | нормализация настроек, URL оверлея, тур (ссылки на `data-tour`)                                                      |
| Python         | `services/tts/tests`       | HTTP-контракт TTS с подменённым голосом                                                                              |

Не покрыто автотестами: реальные Twitch, Anthropic, Piper, сборка Docker-образов,
внешний вид интерфейса. Их проверяют вручную (см. раздел 8).

Интеграционные тесты поднимают одноразовый кластер через `embedded-postgres`.
Docker для них не нужен. Anthropic и TTS в тестах заменены фейками.

## 6. Правила работы с репозиторием

- **Не коммитьте без явной просьбы пользователя.** Не делайте `git add`, `commit`
  или `push` сами. Если коммит кажется полезным, предложите его одной строкой.
- Формат коммит-сообщения: `TYPE(APP): CHANGES`, например
  `feat(worker): add monthly TTS character limit`. Типы: `feat`, `fix`, `docs`,
  `refactor`, `test`, `chore`, `ci`.
- Перед правкой миграций: существующие миграции не редактируются. Новые
  добавляются файлом `NNNN_name.sql` и записью в `packages/db/migrations/meta/_journal.json`.
- Перед изменением публичного контракта (zod-схемы в `packages/shared`) проверьте
  все места использования: `grep -rn "<имя>" services apps packages`.

## 7. Ключевые инварианты (не ломать)

1. **Блок безопасности первый в промпте** (`SAFETY_BLOCK`). Тон и токсичность
   меняют только стиль, не границы.
2. **Ник, вход и выход проходят встроенный стоп-лист** (`packages/prompts/src/blocklist.ts`,
   отключить нельзя; admin- и канальные слова только добавляются). Ник — весь список; вход —
   только `ALWAYS_BLOCKED` (слюры, экстремизм, самоповреждение); выход —
   `outputBlockedCategories(toxicity)`: слюры, экстремизм, самоповреждение и сексуальное
   унижение всегда, грубые оскорбления до 3, мат до 4. Уровень 6 («Ноль сожалений») по стоп-листу
   равен 5. Отличаются правило тона и классификатор: на 6 разрешён личный разнос адресата, включая
   грубые шутки про мамку и семью без описания секса; слюры, угрозы, пожелания смерти,
   самоповреждение, описание секса и всё о детях блокируются и здесь. Это осознанное решение
   владельца: на уровне 6 шутки про семью не считаются сексуальным унижением. Нормализация ловит транслит,
   leetspeak, омоглифы, разбивку и маски. Вход с попыткой инъекции отклоняется до вызова API.
   Выход дополнительно проверяют на ссылки, утечку промпта и дословный повтор входа, затем
   классификатор (Sonnet 5.5); любой ответ кроме `ALLOW` блокируется (fail-closed). Инструкции идут
   только в `system`, данные зрителя — только в user-сообщение, экранированные и в тегах.
   Новое слово в списке — с примером в `MUST_BLOCK`, а если есть риск коллизии, и в `MUST_ALLOW`
   (`packages/prompts/src/examples.ts`; `scripts/classifier-eval.mjs` прогоняет их через две модели
   классификатора перед сменой `classifier_model`).
3. **Параметры запроса — только через `modelRequest()`** (`services/worker/src/models.ts`).
   `temperature` не передаётся никогда (400 на всех моделях). Модели — только Sonnet 5.5 и
   Haiku 5.5 (`MODEL_IDS` в `packages/shared`, API отклоняет любые другие): более крупные модели
   слишком дороги. Sonnet 5.5 не отключает thinking (`disabled` — 400): ему `effort: "low"` и
   запас `max_tokens`; Haiku 5.5 — `thinking: {type: "disabled"}`.
4. **Квоты и бюджет проверяются до вызова API** в транзакции под advisory lock
   (`reserve()` в `services/worker/src/limits.ts`). Стоимость записывается и при успехе,
   и при сбое после вызова Anthropic.
5. **Повторно доставленная задача не тратит квоту.** Если роаст уже не `queued`,
   воркер возвращает его статус без работы.
6. **Очередь без ретраев** (`retryLimit: 0`): роаст старше TTL оверлея не имеет смысла. TTL —
   `overlayTtlSeconds(source)` от `requestedAt`: 2 минуты для ответа чату (команда, слова, тест
   из панели), 10 минут для наград, донатов и событий — у них нет пауз, они приходят пачкой и
   ждут своей очереди в оверлее. Воркер сам отбрасывает устаревшую задачу (`stale_job`).
7. **Аудиоссылка подписывается в момент доставки** (`signAudioPath` в `services/api/src/overlay.ts`), а не в воркере,
   и живёт до `expiresAt` события плюс `AUDIO_URL_TTL_SECONDS`: оверлей получает всю очередь сразу.
   Ссылки на звук и картинку строятся от `PUBLIC_URL` или от зеркала, через которое пришёл сокет
   (`X-RoastBot-Mirror`, только хосты из `OVERLAY_MIRROR_URLS`; реле — `deploy/Caddyfile.relay`).
8. **Оверлейные токены сравниваются через БД.** Перевыпуск токена закрывает открытые сокеты.
9. **Владелец проверяется по БД** (`requireOwner`), а не по JWT.
10. **Cookie сессии `HttpOnly`**, в проде `Secure`.
11. **Регистрация открытая, с тормозами.** Новый вход через Twitch сразу `active`, кроме
    аккаунтов Twitch моложе `signup_min_account_age_days` (или без `created_at`) и входов сверх
    `signup_daily_limit` за UTC-сутки — они `pending` (счёт под advisory lock в колбэке).
    Приглашение, инвайт-ссылка и `TWITCH_OWNER_IDS` пускают без проверок; существующий аккаунт
    сохраняет статус, `pending` снимается, только если вход проходит проверки. `requireUser`
    отвечает `403 pending_approval` и `403 account_suspended`, `/me/session` не отдаёт
    `overlayToken`, пока статус не `active`.
12. **2FA (TOTP, `services/api/src/totp.ts`).** Владельцу обязательна: `requireOwner`
    требует `totp_enabled_at` и `mfaAt` в JWT не старше 12 часов. Новый вход через Twitch
    никогда не несёт `mfaAt`. Проверка кода — под `for update`, 5 ошибок блокируют на
    15 минут, принятый шаг не принимается повторно, резервные коды — только SHA-256.
    Свою 2FA владелец не отключает и не сбрасывает из UI.
13. **Платные голоса только через резерв лимита.** Любой вызов ElevenLabs, Inworld и SpeechKit идёт
    через `speak()` в `services/worker/src/tts.ts` после `reserveCharacters` (ElevenLabs и Inworld) /
    `reserveYandexRequests` (атомарный upsert в `tts_usage_monthly`). Нет резерва — нет запроса,
    звучит следующий голос. Цепочка: ElevenLabs → Inworld → Яндекс → Piper. **Piper только
    аварийный**: звучит, лишь когда все облачные голоса роаста отказали; `economyVoiceSchema` —
    только `yandex`, ни тариф, ни исключение канала не выбирают Piper (CHECK в `plans` и
    `channel_overrides`). Лимит ElevenLabs — `elevenLabsCharLimit()` (не выше тарифа), счётчик раз в
    5 минут перезаписывает расход самого ElevenLabs (`syncElevenLabsUsage`); лимит Inworld —
    `inworld_monthly_char_limit`. Голоса героини — `cloudVoicesFor()`: своя с голосом Мицуки или Аи
    после ElevenLabs идёт к их Inworld-голосу (`INWORLD_VOICE_*`), с голосом Inworld — сразу к нему.
    Владелец может начать цепочку хороших роастов канала с Inworld или Яндекса
    (`channel_overrides.best_voice`, `firstVoice()` в воркере; роасты, реплики harem-mode и
    заглушки), но не с Piper и не в обход резервов.
14. **Новые триггеры выключены по умолчанию** (`DEFAULT_TRIGGERS` в `packages/shared`): обновление
    никогда само не начинает жарить чат. Логика чата и событий — чистые функции в
    `services/twitch/src/triggers.ts`; кулдауны только для `COOLDOWN_SOURCES`. Кого жарить решает
    `targetMode` канала в воркере; `!роаст` — только для `COMMAND_PLANS`, проверка и в сервисе
    чата, и в воркере.
15. **Тир роаста решает `reserve()`.** `bookTier()` под тем же lock бронирует
    `usage_monthly.premium_roasts` до `plans.premium_roasts` («хорошим голосом»); дальше —
    `economy_model` и Яндекс до `monthly_roast_limit` («потом Яндексом»), затем стоп до следующего
    месяца. Все числа тарифа задаёт владелец в `/admin`, seed их только вставляет (Free 15 + 85,
    Basic 500 + 200 за 300 ⭐, Premium 1000 + 500 за 600 ⭐, миграция 0022). Стример видит тариф одной
    строкой `planVoiceText()` (`packages/shared`). Классификатор на всех тирах один и тот же.
16. **Тесты из панели (`dashboard_test`) не тратят квоту канала** и не проверяют кулдауны, но
    проходят kill switch, глобальный лимит и бюджет и бронируют `test_usage_daily` атомарным
    upsert до `DASHBOARD_TEST_DAILY_LIMIT`. Симулятор формирует событие в API
    (`services/api/src/simulator.ts`), формулировки — как в `services/twitch/src/triggers.ts`.
17. **Память и игра — только данные.** История зрителя (`viewerHistory()` в воркере) и игра идут
    в user-сообщение в `<history>` и `<game>`, экранированные; правило памяти в `system` есть
    только когда история есть. «Just Chatting» не передаётся (`gameContext()`).
18. **Оплата звёздами только по подтверждённому платежу.** `pre_checkout_query` проверяет канал
    и цену, тариф даёт только `successful_payment`; `star_payments.charge_id` — первичный ключ,
    повторный апдейт ничего не добавляет. Вебхук принимает запрос только с
    `X-Telegram-Bot-Api-Secret-Token` (`timingSafeEqual`).
19. **Уведомления стримеру — один раз за период** через `notifications_sent`; уведомление никогда
    не задерживает и не роняет роаст. Telegram-коды привязки хранятся только как SHA-256.
20. **Отказ зрителя** (`viewer_optouts`): `OPTOUT_SKIPPED_SOURCES` пропускаются, остальное — на
    стримера, без истории. Витрина: звезду ставит стример (согласие), показывает владелец.
21. **Демо на лендинге — те же проверки и общий бюджет.** `processDemo()` в
    `services/worker/src/demo.ts`: стоп-лист и инъекции до модели, классификатор после, модель —
    основная (`model`, как у Premium), голос только через `speak()` с `piper: false` и
    `best: "elevenlabs"`. ElevenLabs — через `demoVoiceReservations()`: своя доля
    `demo_elevenlabs_char_limit` (счётчик `elevenlabs_demo`) и общий лимит бронируются вместе в одной
    транзакции, иначе ни один; дальше Inworld и Яндекс. Лимиты на IP и в день — в API под advisory lock;
    расход демо входит в бюджет в `reserve()` (`demoSpendSql`). IP хранится только как HMAC.
22. **Своя героиня — только Premium и только через проверку для чужих каналов.** `characters`
    (`services/api/src/characters.ts`): автор пользуется своей сразу, в магазин (`published`) её
    пускает только владелец, опубликованную нельзя менять. Картинка перекодируется в WebP через
    `sharp` (метаданные отбрасываются) и вместе с сэмплами голосов хранится в БД — попадает в
    `pg_dump`. Воркер берёт героиню, только если тариф в `CUSTOM_CHARACTER_PLANS`, она своя или
    `published` и с картинкой; иначе — встроенная. Имя героини — данные: `characterNameSchema` +
    стоп-лист, в промпт только в `<name>` user-сообщения. Сэмпл голоса — задание `voice.sample`
    через `speak()` с резервом ElevenLabs и без запасного голоса. Отклик на имя в чате
    (`nameMention`) выключен по умолчанию.

23. **Чат — частота, паузы тарифа и заглушки; награды и события — всегда.** Слова-триггеры
    отвечаются раз в `KEYWORD_EVERY[chatFrequency]` (`EveryNth` в сервисе чата). Награда за баллы
    отвечается каждая: её нет в `COOLDOWN_SOURCES` и `VIEWER_LIMITED_SOURCES`, тормоз — цена,
    которую задал стример; квоту, бюджет и kill switch она проходит как всё. `declined` в задаче —
    наследие, сервис чата его больше не ставит. Паузы никогда не ниже `minCooldownSeconds(plan)`
    (`effectiveCooldown` в `reserve()` и в API), один зритель — не больше `VIEWER_ROAST_LIMIT`
    ответов за `VIEWER_ROAST_WINDOW_MINUTES` в `reserve()`.
    Команда, награда и вызов по имени персонажа (`named`, `isStubCall()`), которым нельзя ответить
    роастом (пауза, лимит зрителя, исчерпанная квота или бюджет; у награды пауз и лимита зрителя
    нет, ей остаются квота и бюджет), слышат заглушку (`playStub()`
    в `services/worker/src/stubs.ts`): без квоты и модели, одна заглушка на зрителя в очереди
    оверлея (повторная проверка под lock на зрителя в `publishStub()`). Половина заглушек — голосовые
    (`speak()` и `stub_audio`); вторая половина — бесплатные (`playVisualStub()`): аватар, подпись
    из `STUB_VISUALS` и звук эффекта без голоса. «Мммммм, нет!» (`stub_declined`) остался только для
    задач старого формата с `declined`.
    Одна подпись (`aiDraft`) пишется Haiku под зрителя, проходит проверку выхода и классификатор,
    при отказе — шаблон. Обычные слова-триггеры молчат вне частоты и во время паузы: это болтовня,
    заглушка на неё попадает невпопад. Молчат также бот-аккаунты, игнор-лист, opt-out,
    заблокированный ввод, команда на бесплатном тарифе, глобальный выключатель и события (битсы,
    сабы, рейды, прогнозы, реклама, донаты). Слова в чате пишет `chat_model`, остальное — `model`;
    системный промпт — `systemBlocks` с точками кэша, блок безопасности первый.

24. **Исключения из тарифа — только владелец и только на канал.** `channel_overrides`
    (`channelOverrideSchema` в `packages/shared`): `null` — значение тарифа. Флаг `unlimited` и
    канал владельца (`role='owner'`) обходят в `reserve()` квоту, паузы, лимит зрителя и тестов,
    в сервисе чата — частоту и проверку тарифа для команды и героини; тир всегда `premium`,
    модель — `override.model ?? UNLIMITED_MODEL` (вся маршрутизация моделей — `pickModel()`). Kill switch, бюджет, общий лимит сервиса,
    резервы голосов, стоп-лист и классификатор не обходятся никогда. Классификатор не
    переопределяется. Запросы самого стримера идут в очередь с `STREAMER_JOB_PRIORITY`.
    Токсичность 6 — только при `channel_overrides.zero_regrets` или на канале владельца: API отвечает
    `403 zero_regrets_not_allowed`, а сохранённая 6 без галочки читается и играет как 5
    (`loadContext()`). На уровне 6 донат, команда, вызов по имени и награда идут к
    `ZERO_REGRETS_MODEL` (`zeroRegretsUsesSonnet()`), обычные слова чата — к модели чата канала.
    Обращение к героине по имени или как к боту («говорилка», «бот», «нейросеть» —
    `addressesCharacter()`, или `named`) на уровне 6 всегда бьёт
    автора, кроме событий без автора и opt-out, и добавляет в промпт `[ОБРАЩЕНИЕ К ТЕБЕ]`.
    Примеров ответов в правилах уровня 6 нет намеренно: модель копирует их всем.

25. **Воркер параллельный** (`WORKER_CONCURRENCY`, по умолчанию 4, и можно запускать несколько
    воркеров). Любая проверка «уже есть / ещё нет» перед записью делается под advisory lock в той
    же транзакции, что и сама запись: квоты и паузы — в `reserve()`, одна заглушка на зрителя —
    в `publishStub()`. Проверка до lock — только дешёвый фильтр. Тесты на это —
    `Promise.all` в `pipeline.integration.test.ts`.

26. **Harem-mode (`triggers.haremMode`, выключен по умолчанию).** После готового роаста с шансом
    `HAREM_RETORT_CHANCE` (20 %) в спор вступает встроенная героиня другой темы (`rivalTone()`:
    Мицуки ↔ Аи, своей героине — по `ARCHETYPE_THEME`). `playRetort()` в
    `services/worker/src/retort.ts`: квоту не тратит, но перед вызовом проверяет kill switch и
    бюджет (`extraSpendAllowed()` под тем же lock), промпт `composeRetortPrompt()` — блок
    безопасности первый, реплика первой героини — данные в `<said>`. Выход проходит стоп-лист,
    проверку на повтор и `<msg>`, и `<said>`, и классификатор; голос — только `speak()` с
    `piper: false`. Любой отказ — тишина, роаст не падает, расход записывается. Не бывает после
    заглушки, заблокированного ответа (fallback) и для зрителя с opt-out. Реплика — второе событие
    оверлея того же роаста (`overlay_events.part = 1`), текст — `roasts.retort_text`; все `join`
    с `overlay_events` по роасту берут `part = 0`.

27. **`!топ` (`triggers.topBoard`, выключен по умолчанию).** Бот читает чат анонимно и писать в него
    не может, поэтому табло — карточка в оверлее со звуком (`playBoard()` в
    `services/worker/src/board.ts`): без модели, голоса и квоты, на любом тарифе. Не чаще
    `TOP_BOARD_COOLDOWN_MINUTES` на канал — проверка и публикация в одной транзакции под lock.
    Считаются готовые роасты по вызовам зрителей за `TOP_BOARD_WINDOW_HOURS`; стример, opt-out и
    ники, которые сейчас ловит стоп-лист, не показываются. `!топ` и `!top` нельзя взять командой
    роаста (`RESERVED_COMMANDS`).

28. **Аналитика владельца — только по запросу.** «Расходы» (`/admin/spend`) и «Сервер»
    (`/admin/server`) в `services/api/src/admin-insights.ts` считаются, когда владелец открывает
    вкладку; фоновых задач нет (слабый VPS). Сравнение голосов (`voice.compare`,
    `services/worker/src/voices.ts`) — одна фраза Мицуки и Аи в каждом сервисе строго через
    `speak()` с резервом, без запасного голоса и без Piper.

## 9. Известные ограничения и открытые вопросы

1. **`monthly_tts_limit` не enforce-ится.** Значения в `plans` (20 000 / 60 000 / 300 000
   символов) хранятся, `tts_chars` считается, но лимит нигде не проверяется. Расход голосов
   ограничивают лимиты провайдеров (инвариант 13). Нужно решение: проверять в `reserve()` или
   убрать поле.
2. **Piper не запускается на macOS arm64** (колёса 1.3.0–1.8.0 не находят
   espeak-ng data). Для Linux-контейнера это не проблема, но локально TTS
   проверяется только через `say` в демо.
3. **Лицензия голоса Piper** (`ru_RU-irina-medium`, единственный запасной голос) не
   подтверждена для коммерции. Проверьте карточку на Hugging Face до беты.
4. **Тур**: тексты написаны, но не проверены глазами на реальной вёрстке
   (desktop и телефон).
5. **Лимит в консоли Anthropic** владелец задаёт сам, не ниже `monthly_budget_usd` (по умолчанию
   $10). Приложение дополняет его, но не заменяет.
6. **Голоса своих героинь.** Список — таблица `voices` (колонка `provider`: `elevenlabs` или
   `inworld`): голоса Мицуки и Аи, которые воркер добавляет из `ELEVENLABS_VOICE_*` при старте
   (`syncVoices`) и там же ставит в очередь недостающие сэмплы. При первом старте с
   `ELEVENLABS_VOICE_YANDERE` воркер один раз переводит своих героинь с остальных голосов ElevenLabs
   (пять из `0017`) на голос Аи и выключает их (`custom_voices_moved_to_ai`). **Список голосов
   Inworld пуст:** ключа и ID ещё нет, владелец добавит их в `/admin/characters` (сервис «Inworld»)
   и `INWORLD_*` в `deploy/.env`. Inworld вживую не вызывался: русский язык и поле `language`
   проверить на живом ключе. Когда голоса есть, без голоса героиню не создать.
   После лимита ElevenLabs, на экономичном тире и при выключенном голосе героиня говорит
   Yandex-голосом своего архетипа; голоса Yandex для `kuudere`, `dandere`, `himedere`
   (`CHARACTER_VOICES`) выбраны по документации, на слух не проверены.
7. **Порядок сборки.** `pnpm test` без предварительного `pnpm build` может падать
   из-за отсутствующих `dist/` у workspace-пакетов.

## 10. Чек-лист для нового агента (первый час)
